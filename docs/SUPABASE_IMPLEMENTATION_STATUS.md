# BibleOn Supabase 구현 상태

기준 시각: 2026-09-04 09:43 KST

## 완료

1. **인증**
   - 이메일 회원가입, 로그인, 비밀번호 재설정, 로그아웃, 세션 복원
   - Apple, Kakao, Google OAuth 호출 코드와 Naver custom provider 연결점
   - 로그인 전 개인 기록의 선택적 계정 가져오기와 공유 예시 데이터 폐기

2. **교회와 권한**
   - 교회, 가입 신청, 구성원, 부서 트리, 교회 관리자, 부서 관리자 테이블과 RLS
   - 최대 부서 깊이 5, 부서 삭제 시 상위 부서 이동, 관리자 위임과 관리자/매니저 탈퇴 제한
   - 교회 공지와 예배 준비의 부서 범위 공개 정책

3. **친구, 메시지, QT**
   - 친구 신청/수락/삭제/차단, 1:1·단체·QT 대화, 메시지·읽음·공감·삭제·전송 취소
   - 단체방 초대 시 초대 이전 sequence를 서버 RLS로 차단
   - Realtime 구독과 UI 대화 모델 연결
   - 다른 교회 친구에게는 교회명만 반환하고 부서·직책은 서버 응답에서 제거

4. **개인 데이터 동기화**
   - 성경 읽음, 통독 회차, 진도 기록, 최근 본문, 메모, 강조, 업적, 홈 AI 대화
   - 동일 통독 회차의 읽음 절 합집합 병합
   - 메모 optimistic version과 충돌 사본 보관
   - IndexedDB outbox와 온라인 복귀 재시도

5. **Storage**
   - 사용자 프로필, 교회 프로필, 메시지 첨부파일 private bucket
   - 사용자/교회/대화 참여자 경로 RLS, 파일 크기와 MIME 검사, signed URL
   - 프로필 이미지와 메시지 파일 업로드 UI 연결

6. **검증**
   - 프로덕션 빌드와 저장 경계 검사
   - 15개 로컬 자동 테스트
   - 원격 DB lint
   - 익명 사용자의 핵심 테이블·RPC 접근 차단 및 위조 Storage 업로드 차단
   - 게스트 홈·메시지·성경 탭 브라우저 동작 확인

## 외부 설정 필요

- Google, Kakao, Apple 제공자 콘솔의 client ID/secret과 callback 등록
- Naver OIDC 호환성 확인 또는 인증 브리지 구현
- 실제 이메일이 연결된 테스트 계정 2개를 이용한 JWT 기반 RLS·Realtime 종단간 테스트
- 푸시 알림과 서버 생성 알림은 Edge Function 단계에서 구현

성경 본문은 Supabase DB나 Storage의 매 요청 대상으로 두지 않는다. 앱 정적 자산으로 내려받아
Cache API/향후 모바일 SQLite에 보관하며, 계정이 바뀌어도 재사용한다.
